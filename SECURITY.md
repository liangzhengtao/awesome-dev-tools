# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly.

### How to Report

1. **Do NOT** open a public GitHub issue for security vulnerabilities
2. Email: [security@example.com] or use GitHub's private vulnerability reporting
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial Assessment**: Within 1 week
- **Fix/Update**: Depends on severity
  - Critical: Within 24-48 hours
  - High: Within 1 week
  - Medium: Within 2 weeks
  - Low: Within 1 month

## Scope

This security policy applies to:

- The repository content and configuration
- Any scripts or automation included
- Links to external tools (we verify but cannot guarantee external sites)

## Supported Versions

| Version | Supported |
|---------|-----------|
| Latest  | ✅ |
| Older   | ❌ |

## Security Proven Patterns

When using tools listed in this repository:

1. **Verify downloads** - Always download from official sources
2. **Check checksums** - Verify file integrity when provided
3. **Keep updated** - Use the latest versions of tools
4. **Review permissions** - Understand what access tools require
5. **Use package managers** - Prefer `brew`, `apt`, `winget` over manual installation

## Acknowledgments

We thank security researchers who responsibly disclose vulnerabilities.
